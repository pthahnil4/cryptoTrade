## 2. 新增第三个结束条件：「10 天倒计时」

任务卡现有两个通关条件之外，新增按时间的第三个终止条件。**任一条件命中即本轮结束、进入结算**。

### 2.1 三个并列条件（学习卡）
1. 满 100 次打卡（原有，`filled_count >= 100`）；
2. 任务树全部完成（原有，`_calc_tasks_all_done`，触发提前通关）；
3. **自 `start_time` 起满 N 个日历日（新增，默认 N=10）**。

交易卡：通关仍由资金倍数（settle-round 手动）判定；倒计时到期则终止结算（未翻倍即 `failed`、奖金 0）。

### 2.2 后端（`crypto/plan_routes.py`）
- 常量 `PLAN_COUNTDOWN_DEFAULT`（环境变量 `CRYPTO_PLAN_COUNTDOWN_DAYS` 覆盖，默认 10）；
  每计划可用 `daily_rule.countdown_days` 覆写；`<=0` 关闭。
- 助手：`_countdown_days` / `_calc_days_elapsed` / `_countdown_view` / `_is_countdown_expired`；
  到期批量结算 `_apply_countdown_settlements(plan)`（结算到期卡 → `_recompute_serial_chain` 解锁下一张）。
- `_calc_card_reward` 的返回 `info` 始终附带：`countdown_days / days_elapsed / days_remaining / countdown_expired / countdown_active`
  （→ 经 `_build_plan_stats` 与 `_build_card_detail` 自动贯通到 `/plan/api/list` 与 `/plan/api/card-detail`）。
- **触发点**：
  - `fill-slot` / 补录(backfill) 中，学习卡自动结算条件扩展为
    `filled_count >= 100 or _is_countdown_expired(...)`（同一张卡的窄写，安全）。
  - 新 POST `/plan/api/settle-expired`：走**加锁全树写路径** `_load_plans_for_write` + `_save_plans`，
    幂等结算所有计划内的到期卡并返回最新结构。

### 2.3 为什么结算不在 GET 里做
读接口（list / card-detail / today-status）被前端并发轮询，Flask `threaded=True` 下若在读路径
做全树写事务，远端 MySQL 会撞 `1205 Lock wait timeout` 把整个任务卡页打成 500。
故到期结算走显式 POST：前端加载后若发现任一卡 `reward_info.countdown_expired` 为真，
调用一次 `/plan/api/settle-expired` 落库并重拉刷新（防抖标志 `_cdSweeping` 保证只多跑一轮）。

### 2.4 前端（`crypto/static/js/task_plan.js` + `templates/task_plan.html`）
- 卡片正文新增一行（仅未结算进行中卡显示）：`⏳ 剩余 X 天（第 Y/N 天）`；到期显示"已满 N 天，结算中…"。
- 样式 `.tc-countdown`（灰）/ `.tc-countdown-out`（红）。

### 2.5 生效边界
- **仅未结算 in_progress 卡**纳入倒计时；`completed` / 已结算 / 锁定 pending 卡 `countdown_active=false`、
  `days_remaining=0`，不受影响。
