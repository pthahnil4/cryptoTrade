## 1. 系统架构设计

### 1.1 双仓位架构（趋势跟踪 + 区间波动）

系统在**同一个合约**上并行运行两个相互独立的逻辑仓位：

| 仓位 | 标识 | 策略 | 说明 |
|---|---|---|---|
| 趋势跟踪仓 | `trend` (BUCKET_TREND) | Pro3 趋势信号限价挂单 | 单周期双向 / 双周期单向两种模式 |
| 区间波动仓 | `range` (BUCKET_RANGE) | BOLL 边界限价循环 | 固定双周期单向，无限循环刷区间 |

两个仓位**独立配置张数、独立记账、互不干扰**（不按本金比例分配）。

### 1.2 交易所隔离约定（净持仓模式）

OKX 账户为净持仓（net）模式，同一保证金模式下多空会互相抵消。系统约定：

- **全仓模式(cross)专门持有多头仓位**
- **逐仓模式(isolated)专门持有空头仓位**

即：开多 → cross 买入；开空 → isolated 卖出；平多 → cross 卖出(reduce-only)；平空 → isolated 买入(reduce-only)。

同方向的两个逻辑仓位（趋势/区间）共享同一模式的净头寸，交易所侧无法区分归属，因此**本地账本是仓位归属的唯一依据**。

### 1.3 本地记账机制

由 `DualPositionOrderManager`（`utils/position_order_manager.py`）维护，状态持久化到 `position_order_state.json`：

- 每个 `inst_id` 下分 `trend` / `range` 两个篮子（bucket）
- 每个篮子记录：
  - `held`：`{'long': 张数, 'short': 张数}` 各方向持仓张数
  - `avg_px`：`{'long': 均价, 'short': 均价}` 加权入场均价（加仓时按张数加权更新）
  - `slots`：`entry`（开仓单）/ `exit`（平仓单）两个挂单槽位
  - `algo`：`{'long': rec, 'short': rec}` 交易所侧兜底委托记录（algo_id、触发价、张数）
  - `lev_set`：杠杆已设置缓存（**按 cross/isolated 模式分键**，fx10/L1 修复）
- 槽位状态机：`IDLE → PENDING → FILLED / EXPIRED`（终态入账后归还 IDLE 复用）
- **下单成功立即落盘**（先记账后确认成交，防崩溃丢单）
- 最小交易步长 **0.1 张**，数量按 1 位小数取整

### 1.4 对账机制（reconcile）

每轮调度先查询交易所 cross/isolated 净持仓，与本地账本对账：

- **只缩不增**：交易所实际持仓 < 账本记录（外部平仓/爆仓等）时，按比例摊减两个篮子的 `held`；实际 > 记录时不主动增账（多出部分视为人工仓位，交由反向风控处理）
- 对账前先执行 **兜底委托触发检测**（`poll_algo_triggers`，fx09/M4）：交易所侧止损/止盈委托在断网/停机期间若已触发（state=`effective`），先从对应篮子**定向扣账**（`note_external_close`），避免 reconcile 把这笔减仓按比例错误摊到两个篮子

### 1.5 线程模型

- 调度主循环：`start_real_scheduler()` 每 10s 醒一次，按 `execution_interval_seconds`（默认 60s）触发一轮 `run_real_trading_batch()`
- Flask Web 线程可调用 `force_close_manual()`（人工强平）、`set_manual_override()`（方向干预）
- **`_trade_lock`（RLock）互斥**（fx02/H3）：整轮"分析→对账→反转清理→止盈止损→挂单"与人工强平互斥，强平的"清账本→撤单→平仓"也不被调度轮打断
- `DualPositionOrderManager` 内部另有自己的 `_lock` 保护账本读写

## 2. 交易策略逻辑

### 2.1 Pro3 策略内核（MACD 平滑直方图 + ADX 自适应权重）

策略引擎位于 `crypto/strategy/pro3_singletimeframe.py` / `pro3_dualtimeframe.py`，经 `strategy_adapter.DualPeriodStrategyAdapter` 适配接入，信号逻辑与 backtrader 回测引擎完全一致。

**核心指标**：
- MACD 直方图（histogram）
- 平滑直方图（smoothed_histogram）：按 ADX 自适应权重做指数平滑
  ```
  hist_weight = min(base_weight(0.7) + ADX/200, 1.0)
  curr_weight = 1 - hist_weight
  ```
  ADX 越高（趋势越强）→ 历史权重越大 → 平滑线越钝 → 方向越稳定不易翻转
- 平滑差 = histogram − smoothed_histogram，翻正/翻负是方向信号源

**短周期信号算法（`signal_algo` 可配）**：
- `diff`（默认，灵敏）：平滑差正负直接判向（正=rise/多，负=fall/空），无确认延迟
- `hybrid`（稳定）：混合状态机，与长周期算法一致

**长周期方向：始终使用混合状态机 + MACD 零轴确认**：
- 平滑差翻向后不立即改方向，进入 `waitRise`/`waitFall` 等待态
- 需 MACD 柱站上/跌破零轴才确认翻转，否则维持原方向（带确认延迟，防震荡期来回跳）
- 交易端实际使用**长周期上一时段方向**（`long_prev_direction`）而非当前时段原始值，进一步避免震荡期频繁反转

### 2.2 趋势跟踪仓（period_mode 两种模式）

**single 单周期双向**（当前 NEAR 配置采用）：
- 只看短周期方向，翻转即撤旧单/平旧仓、开新方向，多空都做
- 由 `_trend_single` 执行：目标方向与持仓方向不一致 → 先挂 reduce-only 限价平仓单清旧仓，再挂新方向开仓单

**dual 双周期单向**：
- 只做长周期方向，短周期负责开/平时机，三时段窗口确认：
  - **开仓窗口**：上上时段=反向 + 上一时段=同向 + 当前=同向（翻转后第一个确认周期）
  - **平仓窗口**：上上时段=原向 + 上一时段=反向 + 当前=反向
- 由 `_trend_dual` 执行

**挂单价规则**（不追价）：
- 开仓价 = 反转 bar（短周期上一根已收线 K 线）的 `entry_price_type` 价（默认 close）
- 平仓价 = 反转 bar 的 `exit_price_type` 价（默认 open）
- 挂出后等成交，或等下一次反转信号撤单重挂——宁愿错过不追价

### 2.3 区间波动仓（BOLL 限价循环）

- 固定双周期单向：只做长周期方向
- 长多 → BOLL 下轨挂限价买入开仓、成交后上轨挂 reduce-only 限价平仓；长空反之
- BOLL 参数：短周期 `boll_period`(20) / `boll_dev`(2.0)，由 strategy_adapter 从 df_short 直接计算
- **边界漂移自动改单追价**：边界变动幅度 ≥ `boll_amend_min_pct`（默认 0.001=0.1%）才改单
- 平仓成交后篮子归零，立即重新挂开仓单，无限循环刷区间
- 自带对侧边界止盈，**不参与止盈止损引擎**
- 长周期反转时始终强制处理：未成交挂单撤销换方向重挂、已持仓市价强平

### 2.4 方向覆盖优先级

1. 配置文件 `manual_direction`（long/short）→ 短长周期方向全部强制覆盖，跳过稳定性确认
2. 运行时 `manual_override_cache`（Web 接口 `set_manual_override` 设置）→ 同上
3. auto：短周期用当前方向，长周期用上一时段方向（`long_prev_direction`），缺失时回退当前时段原始值
4. **长周期方向仍缺失（非 long/short）→ 跳过本轮，不做任何交易决策**（fx10/M6，杜绝 `or 'long'` 硬编码看多）

## 3. 实盘执行流程

### 3.1 主循环与批量调度

```
start_real_scheduler()                 # 主循环，10s 轮询
 └─ run_real_trading_batch()           # 每 execution_interval_seconds 一轮，生成 run_id
     ├─ get_real_trading_currencies_from_config()   # 热加载配置；enabled=false 或 emergency_stop=true 直接跳过
     ├─ 逐币种 analyze_and_trade_real(...)          # 单币种完整流程（见 3.2）
     ├─ _print_positions_report()                   # 交易所持仓明细日志
     └─ _save_directions()                          # 全部币种处理完毕才写盘方向记录
```

- 方向记录**轮末写盘**：磁盘方向 = "已完整执行"的方向；中途崩溃/断网重启后仍按旧方向比对，能重新触发长周期反转清理
- 主循环异常记录 `type(e).__name__: {e}` 日志后等待 30s 重试（fx10/M5，不再静默空转）

### 3.2 analyze_and_trade_real 完整步骤

全程持有 `_trade_lock`（finally 释放）：

| 步骤 | 内容 | 失败处理 |
|---|---|---|
| 1 | 双周期趋势分析（strategy_adapter.analyze，BOLL 参数取自区间仓配置） | 返回 None → 本轮终止 |
| 2 | 人工方向覆盖 → 长周期方向缺失检查 | 缺失 → 本轮终止（不交易） |
| 3 | 查询交易所持仓 `_read_positions_by_mode` | 返回 None（网络/API失败）→ 本轮终止，**绝不把查询失败当空仓** |
| 4 | `set_context(run_id)` 设置日志上下文 | — |
| 4a | **兜底委托触发检测** `poll_algo_triggers(trend)`：交易所侧止损止盈已触发 → 定向扣账 | 查询失败保留记录下轮再查 |
| 4-对账 | `reconcile(cross, isolated)` 只缩不增按比例摊账 | — |
| 4b | **成交入账前置** `poll_fills`：上一轮限价单已成交先入账（early_fills），使刚成交的仓位本轮就能进止盈止损检查，而非等下一轮 60s+（fx07/M1） | 幂等，槽位终态不重复入账 |
| 5 | 方向记录：只计算 `long_dir_changed`，**记录更新推迟到步骤6之后**；读一次 `cfg_all`；构建 ctx（含 `max_position` 上限、`trend/range_allow_entry`）；early_fills 按篮子补发成交邮件 | — |
| 5b | **人工强平冷却检查**：冷却期内两仓位均禁止开新仓（平仓/撤单照常）（fx02/H3） | 到期自动清除并写盘 |
| 6 | **长周期反转处理**（见 3.3） | 清理失败保留旧方向下轮重试（fx01/H1） |
| 7 | 反向持仓风控（仅 dual 单向模式启用；single 双向模式自动解除）（见 5.2） | 异常仅记日志 |
| 8 | 止盈止损检查 `_check_tp_sl`（仅趋势仓）；全平触发 → 本轮趋势仓禁开新仓 + 刷新持仓 | 平仓失败下轮重试 |
| 9 | 依次调度：`_run_trend_position` → `_sync_trend_algo`（兜底委托同步） → `_run_range_position` | — |
| 10 | 本轮结构化摘要（七要素）：①趋势方向 ②策略类型 ③信号验证 ④成交情况（含 early_fills）⑤持仓状况 ⑥止盈止损 ⑦风险控制 | — |

### 3.3 长周期方向反转处理（步骤6，fx01/H1 核心）

`long_dir_changed = prev_long 存在且 != long_direction` 时：

1. **区间仓**：旧方向持仓 ≥ 0.05 张 → `_close_bucket` 市价强平（未成交挂单由 process_range 撤单换向重挂）
2. **趋势仓**：仅当 `period_mode='dual'` **且**处于东八区睡眠时段（night_force_close，默认 0-6 点）**且**旧方向持仓 ≥ 0.05 张 → 强制平仓并清止盈引擎状态；否则只发提醒邮件不动仓
3. 发送方向反转提醒邮件（附强平说明）
4. 有平仓动作 → `_refresh_positions` 刷新持仓与账本对账基准
5. **cleanup_ok 判定**：
   - 全部清理成功 → 更新 `last_directions` 为新方向
   - 任一失败 → **保留旧方向记录**（下轮 `long_dir_changed` 重新成立自动重试），且本轮 `trend_allow_entry`/`range_allow_entry` 均置 False，避免新旧方向仓位并存

### 3.4 平仓动作后的持仓刷新

`_refresh_positions`：平仓后重新读取交易所持仓，同步 ctx 并 reconcile。后续挂单量的 reduce-only 封顶依赖真实持仓，沿用旧值会挂出超量平仓单被交易所拒单。查询失败返回 False 沿用旧值。

## 4. 挂单与本地账本管理器

`DualPositionOrderManager` 关键方法与规则：

### 4.1 挂单执行

| 方法 | 职责 |
|---|---|
| `_place_entry` | 限价开仓：先按需设杠杆 → **仓位上限检查（fx06/H4）** → 下单成功立即记 PENDING 落盘 |
| `_place_exit` | reduce-only 限价平仓：挂单量经 `_exit_room` 软件封顶（min(账本持仓, 交易所该模式净持仓的可平余量-已挂平仓量)），防超量拒单 |
| `_amend_slot_price` / `_amend_slot_size` | 改单（区间仓边界追价 / 数量修正） |
| `_cancel_slot` | 撤单（含竞态处理，见 8.1） |
| `_set_leverage_if_needed` | 杠杆设置缓存按 cross/isolated 分键，切模式不漏设（fx10/L1） |

**仓位上限检查（`_place_entry`，fx06/H4）**：`max_position > 0` 时，统计该合约两篮子双向 `held` + 已挂 PENDING 开仓单量，`occupied + 本次挂单量 > max_position` → 拒单并告警。上限值来自 `global_settings.risk_control.max_position_per_currency`，经 plan 逐层传入。

### 4.2 成交入账

- `_reconcile_slot`：查询 PENDING 槽位订单状态 → `filled` 全量入账（`_credit` 更新 held/加权均价 + `_journal_credit` 写交易流水）置 FILLED；`canceled` 部分成交入账后置 EXPIRED；超时过期撤单
- `poll_fills(inst_id)`（fx07/M1 新增）：对全部篮子×槽位跑一遍 `_reconcile_slot`，供步骤 4b 前置入账调用，幂等
- `_credit` 加仓公式：`新均价 = (旧均价×旧张数 + 成交价×成交张数) / 总张数`

### 4.3 方向翻转处理（single 模式 / 区间换向）

`_trend_single` / `process_range` 检测目标方向与槽位方向不一致时：撤单 → 挂新方向。
**槽位复位尊重 PENDING**（fx03/H2 衍生修复）：撤单不确定（`_cancel_slot` 返回 False 且保持 PENDING）时**不强制复位槽位**，防止冲掉待确认订单丢账。

### 4.4 交易所侧兜底委托（exchange_algo_backup）

- `sync_exchange_algo`：按本地账本均价推导触发价，挂/改/撤交易所策略委托（conditional），断网/程序停止/睡眠时仍能触发；本地评估并行运行，谁先触发算谁
- 只有**固定目标止盈**与**固定/ATR 止损**能表达为静态触发价（`tp_engine.exchange_backup_levels` 计算），其余四类止盈仍靠本地评估
- 持仓量/均价变化 → 自动改挂；无持仓/开关关闭 → 撤销
- `poll_algo_triggers(inst_id, bucket)`（fx09/M4 新增）：每轮 reconcile **之前**查询已挂 algo 状态：
  - `effective`（已触发）→ `note_external_close` 定向扣账 + 清记录
  - `order_failed` → 清记录
  - `canceled`（被外部撤销）→ 只清记录，待下轮重挂
  - 查询失败 → 保留记录下轮再查

## 5. 风险控制体系

### 5.1 风控层级总览

| 层级 | 机制 | 配置项 |
|---|---|---|
| 全局 | 紧急停止（跳过全部执行） | `risk_control.emergency_stop` |
| 全局 | 策略总开关 | `global_settings.enabled` |
| 币种 | 单币种仓位上限（下单前硬拦截） | `risk_control.max_position_per_currency`（当前 100 张） |
| 趋势仓 | 止损（最优先检查）+ 六类止盈 + 交易所兜底委托 | `trend_position.stop_loss / take_profit / exchange_algo_backup` |
| 区间仓 | 对侧 BOLL 边界止盈（结构自带） | — |
| 账户 | 反向持仓风控（预警→超时强平：账本内程序旧方向残留仓 + 账本外人工反向单） | `reverse_position_guard` |
| 账户 | 睡眠时段长周期反转强平 | `night_force_close` |
| 人工 | 强平 + 冷却期禁自动开仓 | `manual_close_pause_minutes` |

### 5.2 反向持仓风控（reverse_position_guard）

**适用条件**：仅趋势仓为 `dual` 双周期单向模式时启用；`single` 双向模式下多空持仓均为合法策略仓，自动关闭并解除已有预警。

**检测逻辑**（`_detect_reverse_position`，TRT L454-496）：
- 与长周期方向相反的"另一模式"净持仓（程序约定：多头仅全仓 cross、空头仅逐仓 isolated），分两类来源计量：
  1. **账本内（ledger）**：程序自身的旧方向残留仓。双周期单向模式下两个篮子都只应持有长周期方向，账本里的反向持仓即与设计方向冲突（2026-09-02 LIT 事故修正：长周期反转发生在白天时，步骤6 只在睡眠时段强平趋势仓，旧方向多头既逃过反转清理、又因旧实现"扣除本地账本"被判为无反向持仓，永久裸露且无保护）
  2. **账本外（unbooked）**：真实净持仓超出账本记录的部分，即人工反向开仓
- 账本外超出量阈值取该合约 **minSz**（非硬编码 0.05）：更小的量低于最小可交易量，`_close_amount` 会拒单导致"检测→强平失败→重试"死循环（fx08/M2）

**处置流程**（`_check_reverse_position_guard`，TRT L531-692）：
1. 首次检测 → 立即发预警邮件（含冲突来源：程序旧方向持仓 / 账本外人工反向单），记录计时器（持久化 MySQL `reverse_guard` 表，重启不重置）
2. 超过 `grace_minutes`（默认 10 分钟）未处理 → 强制平仓（`_close_reverse_conflict`，TRT L498-529）：账本内旧方向仓按篮子市价全平并同步扣账本（走 `_close_bucket_smart`，scene=`reverse_guard` 不在智能减仓白名单 → 退化全量平仓，粉尘自动清零）；账本外人工反向单定量 reduce-only 强平；两部分合计恰为该模式真实净持仓，不误伤同向仓位、不超量下单
3. 任一部分强平失败 → 保留计时器不重置（下轮 elapsed 仍超时立即重试），不发"已强平"误报
4. 反向持仓消除（用户自行处理）→ 解除预警
5. 方向反转轮跳过检测（旧方向持仓本轮会被步骤6清理，避免同一轮重复下单）；观察模式只提醒不强平

### 5.3 人工强平与冷却机制（fx02/H3）

`force_close_manual(inst_id, close_type)`（Flask 线程调用，`close_type`: all/long/short）：

1. **持 `_trade_lock`**：等调度轮完整结束后才执行，全程不被打断
2. 先撤两仓位全部挂单并清空账本（`clear_bucket`）——挂单不先撤，强平后残留限价单成交会把仓位开回来；账本不先清，残留 held 会让下轮对账错误归属
3. 清止盈引擎状态
4. 市价平掉 cross 多头 / isolated 空头真实持仓
5. **写入冷却期**：`manual_close_pause_minutes`（默认 30 分钟，0=不冷却）内禁止自动开新仓（平仓/撤单照常），持久化 `manual_pause_state.json` 跨重启保持，到期自动清除并记日志

### 5.4 睡眠时段强平（night_force_close）

- 东八区 `[start_hour, end_hour)` 区间（默认 0-6 点，支持跨零点），显式按 UTC+8 折算不依赖服务器时区（fx10/L4，使用 timezone-aware 的 `datetime.now(timezone.utc)+8h`）
- 该时段内长周期反转 → 趋势仓（dual 模式）强制平仓；时段外仅发提醒邮件

## 6. 止盈止损体系

仅对**趋势跟踪仓位**生效。盈亏一律基于**本地账本均价**计算（净持仓模式下交易所 avgPx 是两仓位混合均价，不可用于单仓位判定）。

### 6.1 检查优先级

```
止损（最优先） → 止盈引擎（时间兜底 → 主止盈六选一）
```
- 全平触发（止损/close_all 止盈）→ 本轮趋势仓不开新仓 + 清止盈引擎状态
- 分批止盈（close_partial）→ 不撤本仓位挂单、不阻断开仓
- 未触发 → 记录监控状态供本轮摘要展示

### 6.2 止损（`_eval_sl`，当前已启用 fx05/H5）

| type | 规则 | 当前配置 |
|---|---|---|
| `fixed` | 亏损 ≥ fixed_pct% 触发 | **enabled=true, fixed_pct=3** |
| `atr` | 亏损价距 ≥ atr_multiple × ATR 触发 | atr_multiple=1.5（备选） |

### 6.3 止盈引擎（TakeProfitEngine，六类主止盈单选 + 时间兜底）

主止盈 `category` 六选一（当前配置 `enabled=true, category=trailing`，pullback_pct 模式：盈利达 1% 激活、峰值回撤 2% 平，fx14 开启）：

| 类别 | 模式 | 规则 |
|---|---|---|
| `none` | — | 不启用主止盈 |
| `fixed_target` | `pct` / `r_multiple` / `atr_multiple` | 盈利达 pct% / N倍R（R=止损距离，止损未启用时 1R=1ATR）/ N倍ATR 全平。**仅本类支持交易所兜底委托** |
| `trailing` | `pullback_pct` / `chandelier` / `r_ladder` | 盈利达 activate_pct% 后峰值回撤 pullback_pct% 平 / 峰值回撤 N倍ATR（吊灯）/ r_levels=[[reach_r, lock_r],…] 阶梯锁利 |
| `momentum` | `hist_decay` / `divergence` | MACD 柱连续 decay_bars 根收缩 / MACD 背离（lookback 回溯），均需盈利 ≥ min_profit_pct% |
| `channel` | `outer` / `middle` | 碰 BOLL 外轨平 / 跌破(升破) BOLL 中轨平（需盈利 ≥ min_profit_pct%） |
| `ladder` | levels | 盈利达各档 pct% 按 close_ratio 分批平当前仓位，末档 1.0 清仓，**已触发档位持久化不重复** |

**时间兜底（time_stop）**：独立开关，可与任意主止盈共存——持仓超 max_bars 根短周期 K 线且盈利仍 < min_profit_pct% → 平仓。

**运行时状态**（峰值价、入场时间、已触发阶梯档位）持久化到 `tp_engine_state.json`（原子写入，fx04/M3）；仓位清零 / 人工强平 / 反转强平时 `clear_state` 清理。

### 6.4 双保险架构

- 本地评估（每轮 60s）：六类止盈全支持，灵活但依赖程序存活
- 交易所兜底委托（exchange_algo_backup=true）：固定止损 + 固定目标止盈挂到交易所侧，断网/停机/睡眠仍能触发；触发后下轮由 `poll_algo_triggers` 定向扣账
- 谁先触发算谁

## 8. 异常处理与容错设计

### 8.1 撤单竞态处理（`_cancel_slot`，fx03/H2）

撤单瞬间订单可能刚好成交（竞态），处理规则：

1. 撤单前先查一次订单信息
2. 撤单失败或首查失败 → **重查一次终态**
3. 终态 `filled` → 全量入账（成交量/价缺失时回退挂单量/挂单价）置 FILLED，返回 False（调用方按"已成交"处理）
4. 部分成交 → 入账已成交部分后复位槽位
5. **两次查询都失败 → 保持 PENDING 返回 False**，下轮再确认——绝不盲目复位丢掉成交尾巴；上层方向翻转分支相应地只在槽位非 PENDING 时才复位

### 8.2 成交入账保证（fx07/M1）

- 步骤 4b `poll_fills` 前置入账：上一轮成交本轮即计入账本 → 止盈止损/反转清理都基于最新持仓
- 入账幂等：槽位已达终态不重复入账
- early_fills 计入本轮摘要④并按篮子补发成交邮件

### 8.3 状态文件原子写入（fx04/M3）

四个状态文件全部采用 **临时文件 + `os.replace`** 原子替换：

- `scheduler_state.json`（方向记录）
- `reverse_guard_state.json`（反向风控计时器）
- `manual_pause_state.json`（人工强平冷却）——以上三者经 trader 的 `_atomic_write_json`
- `position_order_state.json`（本地账本）——`DualPositionOrderManager._save`
- `tp_engine_state.json`（止盈运行时状态）——`TakeProfitEngine._save_state`

防止进程中途被杀（断电/OOM/结束任务）留下截断文件，下次启动解析失败回退空状态导致账本/方向/计时器全丢。

### 8.4 网络与查询容错

| 场景 | 处理 |
|---|---|
| 持仓查询失败（`try_get_positions_by_mode` 返回 None） | 跳过本轮交易——绝不把"查询失败"当"空仓 0"重复开仓；平仓函数同样视为"未平仓"返回 False |
| 分析失败（K线获取/计算异常） | 本轮终止 |
| 长周期方向缺失 | 本轮终止（fx10/M6） |
| 兜底委托状态查询失败 | 保留记录下轮再查 |
| 反向风控强平失败 | 保留计时器（不重置 detected_ts）下轮立即重试，不发"已强平"误报 |
| 长周期反转清理失败 | 保留旧方向记录下轮自动重试，本轮禁开仓（fx01/H1） |
| 邮件发送失败 | 仅记 warning，不影响交易主流程 |
| 主循环异常 | 记录异常类型+信息，等待 30s 继续（fx10/M5） |

### 8.5 平仓量安全

- `_close_amount`：定量市价 reduce-only（多头走 cross、空头走 isolated），一律按张数定量——净持仓下"平掉该模式全部持仓"会误伤另一仓位；量 < 0.1 张拒绝执行
- `_close_bucket`：先撤本仓位挂单（避免残留 reduce-only 单挤占可平数量），平仓成功后同步扣减账本
- `_exit_room`：平仓挂单量软件封顶，防超量拒单
