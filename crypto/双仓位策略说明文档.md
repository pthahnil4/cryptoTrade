## 1. 每轮主调度流程（analyze_and_trade_real，TRT L1876-2290）

整轮被 `self._trade_lock` 互斥（与网页"人工强平"的 Flask 线程互斥，L1909-1911）。
每个币种每轮执行顺序（`execution_interval_seconds=80` 秒一轮，8 币种串行）：

1. **双周期趋势分析**（L1913-1924）：`DualPeriodStrategyAdapter.analyze`，BOLL 参数
   （`boll_period=20`、`boll_dev=2.0`）取自**区间仓配置**，两仓位共用同一份分析结果。
2. **方向决议**（L1940-1962）：`_resolve_directions`（详见 §5.4）。
   长周期方向缺失（K 线不足/异常）→ 整轮跳过，不做任何交易决策（L1964-1969）。
3. **持仓查询**（L1971-1978）：查询失败返回 None → 整轮跳过（宁可不动，
   不把"查询失败"当"空仓 0"而重复开仓）。
4. **观察模式切换 + 对账前置**（L1980-2040）：
   - 进入观察模式首轮：撤销两仓位全部未成交挂单，期间只分析 + 发邮件（L1982-2000）；
   - 4a `poll_algo_triggers`：检测交易所侧兜底委托是否已触发（断网/停机期间可能已成交），
     **必须在 reconcile 之前**定向从趋势仓账本扣减，否则会被按比例摊到两个篮子（串账）；
   - 4b `poll_fills(ttl_seconds)`：上一轮挂单成交先入账 + 挂单 TTL 到期撤销。
     **必须在 reconcile 之前**——否则"账本>真实"缩减分支会把刚成交的限价平仓
     误判为系统外手动平仓，错误触发人工平仓冷却；
   - `reconcile`：本地账本与交易所真实持仓双向拉平（详见 §5.1）；
   - 4c `_detect_external_close`：对账后账本仍缩减 = 系统外持仓减少（手动平仓/强平/爆仓）
     → 进入人工平仓冷却（详见 §5.5）。
5. **反转判定与冷却闸门**（L2042-2132）：
   - `long_dir_changed`：上一轮记录的长周期方向 ≠ 本轮方向（仅先计算，方向记录
     的更新推迟到步骤 6 清理完成之后——清理失败保留旧方向，下轮自动重试）；
   - 风控上限折算（张数/USD 双口径取更严者，USD 口径按纯面值 1x 杠杆折算，
     保证不同杠杆下拦截力度一致，L2048-2067）；
   - 5b 人工强平冷却（`manual_close_pause_minutes=30`）：期内两仓禁止开新仓，
     平仓/撤单照常；
   - 5c 止盈止损冷却（`tp_cooldown_periods` 个短周期，配置缺省时代码默认 **3**）：
     期内两仓禁止开新仓。
6. **长周期反转处理**（L2134-2202，详见 §5.3）。
7. **反向持仓风控**（L2266-2290，详见 §2.6）。
8. **趋势仓止盈止损检查**（L2222-2236，详见 §2.4）。全平触发 → 本轮趋势仓不开新仓
   （区间仓照常，除非同轮启动了冷却则一并拦截）。
9. **两仓位依次调度**（L2238-2245）：`_run_trend_position` → `_sync_trend_algo`
   → `_run_range_position`。观察模式则只走 `_watch_*_alerts` 发提醒邮件。
10. **心跳日志**（L2247-2264）：一行汇总方向/账本/净持仓/风控/动作。

## 2. 仓位A（趋势跟踪）

### 2.1 信号来源与周期配置

- 信号算法：Pro3（`MACD_Smoothed_ADX_Pro3`），`signal_algo='diff'`（默认）/`'hybrid'`。
- 周期：币种级配置 `short_period`（开平时机）+ `long_period`（持仓方向）。
  实盘 8 币种为 5m/15m × 4H/1D 组合。
- 方向提取（SA L126-146）：
  - 当前短周期方向 = 短周期 K 线**最后一根**（最新已收盘）`MODIFY_FLAG`：
    `rise→long / fall→short`；
  - `short_prev_direction` = **倒数第 2 根**（`iloc[-2]`）；
  - `short_prev_prev_direction` = **倒数第 3 根**（`iloc[-3]`）；
  - `long_prev_direction` = 长周期上一时段方向。
- `period_mode`（trend_position 配置）：
  - `'dual'`（默认）：**双周期单向** —— 只做长周期方向，短周期三时段窗口决定开平时机；
  - `'single'`：**单周期双向** —— 只看短周期方向，翻转即平旧开新，无窗口概念。

### 2.2 开仓/平仓窗口（双周期单向模式）

窗口在 `TRT._run_trend_position` L1606-1611 计算：

```
open_window  = (当前短 == 目标方向) and (上一短 == 目标方向) and (上上短 == 反方向)
close_window = (当前短 == 反方向)   and (上一短 == 反方向)   and (上上短 == 目标方向)
```

**审查结论：三时段共振条件正确。**
- 开仓窗口 = 上上=反向 + 上一=同向 + 当前=同向（"反转后连续两根确认"）；
- 平仓窗口与开仓窗口完全对称；
- 窗口持续期：方向延续时窗口**仅持续一根 K 线**（下一根 bar 的"上上"会变成同向，
  窗口自动关闭）；调度周期 80s、短周期 5m 时，一个窗口内约经历 3~4 轮调度；
- 进入开仓窗口的上升沿会发一封提醒邮件（方向 + 参考价 + 计划张数），
  窗口持续期不重复，窗口结束复位（L1612-1623）。

`POM._trend_dual`（L1031-1113）的窗口处理：
- **窗口上升沿**复位对应终态槽位（新一轮挂单机会，L1052-1057）；
- **开仓窗口内**：`need = quantize(目标张数 − 已持仓)`，`need>0` 且槽位非 PENDING
  → 复位并重挂限价开仓单；槽位已 PENDING → 仅改量跟随折算张数变化（L1062-1083）。
  窗口期内被外部撤单/成交后终态的槽位可以复位重挂（窗口剩余 bar 仍有效）；
- **窗口结束**（或 `allow_entry=False`）→ 撤销未成交开仓挂单（L1084-1087）；
- **平仓窗口内**：有持仓时 `target = quantize(min(持仓, 可平封顶量))`，挂
  reduce-only 限价平仓单；终态槽位同样复位重挂（平仓窗口持续期一直尝试平到
  目标量，避免外部撤单后持仓裸露，L1090-1108）；
- **平仓窗口结束**或持仓已清零 → 撤销未成交平仓挂单（L1109-1112）。

### 2.3 单周期双向模式（_trend_single，POM L943-1029）

- `target_dir = 短周期方向`，无窗口概念；
- **方向翻转**（`last_desired` 变化）：撤销上一轮未成交的两槽挂单并复位，
  开启新一轮挂单机会（L959-969）；
- **平仓槽**只服务反向持仓：有反向持仓时按 `exit_px` 挂 reduce-only 平仓单；
  无反向持仓时撤掉/复位平仓槽（L974-997）；
- **开仓槽**：目标方向无仓且 `allow_entry` 且张数>0 → 按 `entry_px` 挂限价开仓单；
- **不追价原则**：挂单被外部撤销（EXPIRED）或成交后（FILLED）本轮**不补挂**，
  等下一次方向翻转信号（L991 注释）。唯一例外：FILLED 后持仓又被清零
  （人工平仓/强平）且方向未变 → 复位终态槽位重挂（L1015-1019），
  否则人工平掉后方向不翻转就永远不会再开仓。

### 2.4 限价挂单价取值规则

- 配置 `entry_price_type`（默认 `'close'`）/ `exit_price_type`（默认 `'open'`）；
- 取**触发反转的那根短周期 K 线**的价格：`reversal_close` 或 `reversal_open`
  （由策略引擎 `get_latest_data_dual` 计算并返回），缺失时回退本轮现价
  （TRT L1582-1585）；
- 开仓限价单含义：做多时挂在反转 bar 收盘价附近等回踩成交（不追价），
  成交不了就等窗口结束撤单 / 下次反转。

### 2.5 止盈止损机制（只作用于趋势仓）

评估优先级（`_check_tp_sl` L1248-1403）：**止损 → 时间兜底 → 六类主止盈（单选互斥）**。
盈亏一律基于**本地账本均价**计算（净持仓模式下交易所 avgPx 是两仓位混合均价，不可用）。
对 long/short 两个方向分别评估（双向模式下可同时持有）。

**止损**（`_eval_sl` L1422-1438，最优先）：
| 类型 | 条件 |
|---|---|
| `fixed` | 亏损% ≥ `fixed_pct`（默认 3%） |
| `atr` | 亏损距离 ≥ `atr_multiple` × ATR（默认 1.5） |

止损触发 → 市价全平该方向趋势仓（`_close_bucket`，先撤本仓位挂单）→ 成功启动冷却。

**六类主止盈**（TPE，`category` 单选）：

| 类别 | mode | 触发条件 |
|---|---|---|
| 1. `fixed_target` 固定目标 | `pct` | 盈利% ≥ `pct`（默认 5%） |
| | `r_multiple` | 盈利距离 ≥ N×R（R=止损距离；止损未启用时 1R=1ATR） |
| | `atr_multiple` | 盈利距离 ≥ N×ATR（默认 3） |
| 2. `trailing` 追踪 | `pullback_pct` | 峰值盈利曾 ≥ `activate_pct`（默认1%）后，从峰值回撤 ≥ `pullback_pct`（默认2%） |
| | `chandelier` | 曾进入盈利后，价格从峰值回撤 ≥ N×ATR（默认3） |
| | `r_ladder` | 峰值达 `reach_r` 倍 R 时锁定线抬到 `lock_r` 倍 R，跌破锁定线平仓（默认档位 [[1,0],[2,1],[3,2]]） |
| 3. `momentum` 动能衰竭 | `hist_decay` | MACD 柱同向连续收缩 `decay_bars` 根（默认3）且盈利 ≥ `min_profit_pct`（默认0.5%） |
| | `divergence` | 价格创新高(低)但 MACD 柱峰值降低（顶/底背离）且盈利达标 |
| 4. `channel` 通道边界 | `outer` | 多头触及 BOLL 上轨 / 空头触及下轨（**须处于盈利**，避免开仓即在轨外误平） |
| | `middle` | 多头跌破中轨 / 空头升破中轨，且盈利 ≥ `min_profit_pct`（默认0） |
| 5. `ladder` 分批 | `levels` | 盈利达各档 `pct` 时按 `close_ratio` 比例平当前仓位；档位持久化不重复触发；末档/合并≥99.9% = 清仓 |
| 6. `time_stop` 时间兜底 | — | **独立开关，可与任意主止盈共存且优先**：持仓 ≥ `max_bars` 根短周期 K 线（默认24）且盈利仍 < `min_profit_pct`（默认1%）→ 全平 |

运行状态（峰值/谷值/入场时间/已触发档位）持久化到 MySQL `tp_runtime_state` 表，
重启不丢失；持仓归零后 `clear_state` 清理（TPE L141-150）。
旧版配置兼容：`type='fixed'/'trailing'` 自动映射为 `fixed_target`（TPE L84-104）。

**动作语义**：
- `close_all` → 市价全平 → 成功后启动止盈止损冷却（本轮起两仓禁开新仓）；
- `close_partial`（仅分批止盈）→ 按比例定量市价减仓，**不撤挂单、不阻断开仓**；
  末档（剩余不足该合约 minSz）等同全平，同样启动冷却（TRT L1392-1396）；
- 止盈/止损平仓失败 → 下轮重试，不启动冷却。

**当前配置实况**：8 币种的 `take_profit.enabled=false`、`category='none'`，
`stop_loss.enabled=false` —— 即本地止盈止损目前**全部未启用**，
趋势仓平仓只靠平仓窗口与反转清理（如需启用须逐币种配置）。

### 2.6 交易所侧兜底委托（exchange_algo_backup）

本地评估为主，交易所委托只是"保险"（`_sync_trend_algo` TRT L1633-1658）：

- 开关：`trend_position.exchange_algo_backup`（默认 true）且仓位启用；
- 每轮对 long/short 两方向：有持仓（>0.01 张）且有均价 → 推导触发价并同步；
  无持仓/开关关 → 撤销已有兜底委托；
- **只有可表达为静态触发价的部分能下发**（TPE L253-318）：
  - 止损：`fixed`（均价×(1±pct%)）/ `atr`（均价±N×ATR）；
  - 止盈：仅 `fixed_target` 的三种 mode（均价±目标距离）；
  - 追踪/动能/通道/分批/时间兜底依赖运行时序列 → 只能本地评估，
    日志注明"{category}止盈依赖运行时状态，仅本地评估"；
- 同步规则（`POM.sync_exchange_algo` L1368-1438）：
  - 委托量 = `quantize(min(传入量, 篮子持仓))`；
  - 量差不足一个下单步长、触发价变化 <0.1%（`_px_eq`）→ 视为未变，保留现委托；
  - 参数变化 → 撤旧重挂；持仓归零/无有效触发价 → 撤销；
  - 触发价基于**本地账本均价**，委托量不超过本篮子持仓（避免误平另一篮子）。
- **触发检测**（`poll_algo_triggers`，每轮对账前执行）：
  - `state=effective`（已触发、市价平仓已执行）→ 定向扣减趋势仓账本（防串账）；
  - `order_failed` → 清理记录；`canceled` → 清理，下轮自动重挂；
  - 查询失败保留记录下轮再查（不盲目清理）。

### 2.7 特殊场景处理

**① 睡眠时段强平**（`night_force_close`，配置 enabled、UTC+8 0-6 点）：
- 仅在**长周期反转**发生时生效，且仅 **dual 模式**趋势仓：
  睡眠时段内反转 → 趋势仓旧方向持仓也强平（走 `_close_bucket_smart`，scene=`night_force`）；
  白天反转 → 趋势仓保持不动，只发提醒邮件（区间仓任何时段都强平换向）；
- 时区判定显式按 UTC+8 折算，不依赖服务器本地时区（TRT L1461-1477）。

**② 反向持仓风控**（`reverse_position_guard`，配置 enabled、grace_minutes=10）：
- 仅 "趋势双周期单向 + 区间单向" 时开启；`period_mode='single'` 时自动解除
  （单周期双向模式反向持仓属正常状态，TRT L2280 前后）；
- 检测：与长周期方向相反的"另一模式"净持仓，分两类来源分别计量（TRT L454-496）：
  1. **账本内（ledger）**——程序自身旧方向残留仓（2026-09-02 LIT 事故修正：
     长周期反转发生在白天时，步骤6 只强平区间仓，趋势仓旧方向多头逃过清理后
     旧实现"扣除本地账本"使其对风控隐形，永久裸露且无保护）；
  2. **账本外（unbooked）**——人工反向开仓（真实净持仓超出账本记录的部分），
     超出量 < 该合约 minSz 视为粉尘不计入；
- 流程：首次检测 → 立即预警邮件（含冲突来源）→ 每轮倒计时提醒（同分钟去重）→
  超 `grace_minutes` 未处理 → 强制市价平仓：账本内旧方向仓按篮子全平并扣账本
  （`_close_bucket_smart`，scene=`reverse_guard` 退化为全量平仓），账本外人工单
  定量 reduce-only；两部分合计=该模式真实净持仓，不误伤同向仓位、不超量下单；
- 任一部分强平失败保留计时器下轮立即重试（不重置、不误报"已强平"）；
  反向持仓消除（用户自行处理）→ 解除预警。观察模式只提醒不强平；
  反转轮跳过检测（旧方向仓当轮由步骤6 清理，避免重复下单）。

**③ 手动平仓冷却**（`_detect_external_close`，TRT L410-452）：
- 对账后账本缩减 ≥0.1 张 → 判定系统外减仓 → 进入 `manual_close_pause_minutes`
  （=30 分钟）冷却，期间两仓禁止开新仓（平仓/撤单照常）；
- 程序自身平仓不会误触发（市价平仓即时入账、限价成交在 reconcile 前入账、
  兜底委托触发在对账前定向扣减——入账顺序是刻意设计的）。

**④ 观察模式**（币种级 `trade_enabled=false`）：
- 对交易所零操作：不下单/不撤单/不平仓/不启动冷却/不清引擎状态；
- 进入首轮撤全部挂单；反转清理冻结（重新开启后自动补执行）；
- 开仓窗口/止盈止损/反向持仓等事件按上升沿去重发邮件提醒。

## 3. 仓位B（区间波动）

### 3.1 BOLL 边界入场逻辑（_run_range_position，TRT L1660-1698）

- **固定双周期单向**：方向 = 决议后的长周期方向（受人工方向锁定约束）；
- BOLL 参数：`boll_period=20`、`boll_dev=2.0`（币种级配置，与趋势分析共用一次计算）；
- 挂单价：
  - 长多：**下轨限价开多**（`entry_px = boll_lower`），**上轨限价平多**（`exit_px = boll_upper`）；
  - 长空：**上轨限价开空**，**下轨限价平空**；
- BOLL 边界不可用（上/下轨 ≤0）→ 本轮不挂单并告警；
- 下单量：`_resolve_size`（张数/金额双模式，详见 §6.2）。

### 3.2 生命周期（无限循环刷区间，POM.process_range L1119-1230）

```
无持仓 → 开仓边界挂限价开仓单（可被反复重挂）
   │ 成交
   ▼
有持仓 → 撤开仓单，立即在对侧边界挂 reduce-only 平仓单（对侧边界止盈）
   │ 成交
   ▼
持仓清零 → 释放开仓槽 → 下一轮重新挂开仓单 → 循环
```

- **开仓槽**（仅无持仓时有效）：
  - 已持仓或 `allow_entry=False` → 撤销/复位开仓单；
  - 槽位 PENDING 且方向相符 → **追价改单 + 改量**（见 §3.3）；
  - 槽位处于 IDLE / FILLED / EXPIRED 任一状态且张数、价格有效 → **重挂**
    （这是"无限循环"的关键：平仓成交/外部撤单后都会重新挂出开仓单，L1189-1199）；
- **平仓槽**（仅有持仓时有效）：
  - 持仓清零 → 撤销/复位；
  - 有持仓 → `target = quantize(min(持仓, 可平封顶量))`，挂/改对侧边界平仓单
    （L1201-1227）；
- **成交联动**：开仓成交 → 立即释放平仓槽（终态复位），同轮即可挂平仓单；
  平仓成交 → 释放开仓槽（`_reconcile_slot` L494-497）。

### 3.3 追价改单机制（amend）

- **改价**（`_amend_slot_price`，POM L654-679）：BOLL 边界每轮重算，
  挂单价追随新边界；变化幅度 < `boll_amend_min_pct`（默认 0.001=0.1%）不改
  （避免频繁改单）；改价失败保留原价下轮重试；
- **改量**（`_amend_slot_size`，L681-708）：金额模式下每轮折算张数随价格/配置
  变化，存量挂单必须改量跟随；差值不足一个下单步长视为无变化（按步长比例取整
  比较，规避浮点误差）；目标量为 0 → 撤单；
- 趋势仓**不追价**（窗口结束即撤），追价机制只属于区间仓。

### 3.4 挂单 TTL

- `order_ttl_periods=4`（global_settings）：挂单存续超过 4 个短周期主动撤销后
  同轮按最新价重挂（`_expire_ttl`，POM L1264-1282）；
- 趋势仓挂单通常先被窗口结束撤销，TTL 只是兜底；区间仓是持久挂单，
  靠 TTL 周期性刷新，防止漏撤/崩溃残留单在交易所侧永久存续。

## 4. 两仓位协同与隔离

### 4.1 交易所层面约定

- 账户为**净持仓模式**（不传 posSide），多空靠保证金模式隔离：
  **多头统一全仓（cross）、空头统一逐仓（isolated）**（`_mode_of`，POM L714-717）；
- 两篮子方向相同时共享同一净头寸，交易所无法区分归属 → 本地账本
  （`held` 张数 + `avg_px` 加权均价）是归属的唯一依据；
- 杠杆设置也按模式分键：多头/空头各自设置与缓存。

### 4.2 本地账本记账（_credit，POM L523-548）

- 开仓成交：`held += 成交量`，均价按加权更新 `(原均价×原持仓 + 成交价×成交量) / 新持仓`；
- 平仓成交：`held -= 成交量`，归零（低于粉尘阈值 0.01 张）时持仓与均价一并清零；
- 部分成交：进度记录，终态（filled/被撤）统一入账；
- 撤单竞态保护：撤单前一刻可能已完全成交 → 重查终态把成交尾巴入账，
  绝不盲目复位丢账（`_cancel_slot`，L577-652）；
- 每笔成交写结构化流水 `trade_journal`（实盘 vs 策略对比引擎数据源）。

### 4.3 对账（reconcile，POM L349-426，每轮一次）

- **账本 > 真实**（系统外减仓：手动平仓/强平/爆仓）→ 两篮子按比例缩减，
  缩到粉尘阈值以下清零；
- **真实 > 账本**（人工同向加仓/入账遗漏）→ 超出部分**吸收进账本**继续管理，
  归属优先级：已持同向仓的篮子（按比例摊）> `last_desired` 同向的篮子 > 趋势仓；
  人工部分入场价未知，用本轮现价近似参与均价；
- 顺序要求：必须在"成交入账（poll_fills）"与"兜底委托扣减（poll_algo_triggers）"
  之后、"手动平仓检测（快照比对）"之前调用。

### 4.4 reduce-only 封顶量（_exit_room，POM L879-898）

```
本篮子可挂平仓量 = 真实同向持仓 − 其他篮子已挂同向平仓量
```

- 净持仓模式下交易所的 reduce-only 只保证不超整仓，无法区分篮子 →
  软件层再封顶，避免两篮子同时挂平仓单导致计划平仓量超过真实持仓；
- 本篮子自己的挂单不计入（供改量目标使用）；
- 只做浮点收敛，步长取整由调用方 `_q()` 统一处理。

### 4.5 长周期方向反转处理流程（步骤 6，TRT L2134-2202）

| 对象 | 白天 | 睡眠时段（UTC+8 0-6 点） |
|---|---|---|
| 区间仓旧方向持仓 | **强平**（智能减仓入口），未成交挂单由 process_range 撤销换向重挂 | 同左 |
| 趋势仓旧方向持仓（dual） | 保持不动，只发提醒邮件 | **强平**（智能减仓入口） |
| 趋势仓（single） | 无需处理：方向翻转即平旧开新是单周期模式的正常行为 | 同左 |

- 观察模式：不清理、不更新方向记录（冻结），重新开启交易后自动补执行；
- **方向记录更新条件**：清理全部成功才记新方向；任一失败 → 保留旧方向记录，
  下轮 `long_dir_changed` 重新成立自动重试，且本轮两仓禁止开新仓
  （避免新旧方向仓位并存）；
- 清理入口统一 `_close_bucket_smart`（智能减仓，见 §4.6）。

### 4.6 智能减仓（_close_bucket_smart，TRT L994-1079）

> **注意：当前配置未启用**——`global_settings` 无 `smart_reduce` 键，
> `enabled` 默认 False，反转清理/睡眠强平实际走**全量平仓**原逻辑。
> 以下为其启用时的行为：

- 平仓前查整仓净已实现盈亏 `realizedPnl`（含手续费/资金费）：
  - `≥ 0`（未亏损）→ 全量平仓；
  - `< 0`（亏损）→ 放弃全平，市价减仓至目标保证金（`target_margin_usd` 默认 0.5U）
    的残留仓，保留持仓记录避免亏损了结计入胜负统计；
- 降级原则：查询失败按原逻辑全平；规格/价格缺失无法算保留量 → 本轮跳过
  （亏损状态绝不因技术故障被动全平）；
- 保留量折算不足 minSz 时按 minSz 保留（否则残留仓将来平不掉）；
- 仅白名单场景生效（默认 `['reversal', 'night_force']`）；
- 残留仓记录持久化到 MySQL（供残留查询接口与人工操作）。

### 4.7 粉尘持仓清零

- 持仓 ≥0.01 张（`POS_DUST`）即算"在场"；
- 平仓路径（`_close_bucket` / `_close_bucket_smart`）中，持仓处于
  `[0.01, minSz)` 区间（低于该合约最小下单量，平仓单必被拒）→ 直接清零账本
  视为已清理；阈值按合约 minSz 取（XRP=0.01 / NEAR=0.1 / POL=1），
  避免把真实可平的小仓误清成幽灵持仓；
- 反转清理门槛同样取 `POS_DUST`：低于 minSz 的旧方向残留也必须进清理入口
  （内部粉尘清零），否则永久留在账本上阻断新方向开仓。

### 4.8 冷却期一览（作用范围）

| 冷却 | 触发 | 时长 | 作用范围 |
|---|---|---|---|
| 人工强平冷却 | 检测到系统外持仓减少 / 网页人工强平 | `manual_close_pause_minutes`=30 分钟 | 两仓禁止开新仓；平仓/撤单照常 |
| 止盈止损冷却 | 趋势仓止盈/止损全平成功（含分批末档） | `tp_cooldown_periods`×短周期（配置缺省→代码默认 3） | 两仓禁止开新仓 |
| 反转清理失败禁开 | 反转清理未全部成功 | 当轮 | 两仓禁止开新仓（下轮重试） |
| 反向持仓风控 | 检测到反向持仓（账本内旧方向残留 + 账本外人工单） | 检测起 `grace_minutes`=10 分钟后强平 | 只强平与长周期方向相反的部分，不拦本方向开仓 |

## 5. 方向决议与人工方向锁定（_resolve_directions，TRT L1826-1874）

### 5.1 来源与优先级

1. 币种配置 `manual_direction`（`'long'/'short'/'auto'`）；
2. 页面运行时锁定 `manual_override_cache`；
3. 两者都无 → 信号驱动。

### 5.2 锁定语义（2026-09-01 语义修正后的现行行为）

- **只锁长周期方向**：`long = long_prev = 锁定方向`；
- **双周期单向模式**：短周期三时段一律保留真实信号 —— 开仓仍须通过真实
  三时段共振窗口（上上=反 + 上一=同 + 当前=同）。锁定不会伪造"刚刚反转"，
  反向信号窗口期不开仓也不反向；
- **单周期双向模式**：方向即持仓方向，短周期三时段一并锁定
  （锁定后不再翻转，持仓保持直到解锁）；
- 方向来源（配置锁定/页面锁定/信号驱动）随挂单原因写入 `trade_operations.log`。

### 5.3 锁定对开仓窗口的影响（重点核对项）

- 锁定**不保证立即开仓**：必须等短周期出现真实的"反向→同向"转换才有开仓窗口。
  若锁定时短周期已连续多根同向（如上上根已同向），窗口条件不成立，暂不挂单——
  这是正确行为（防高位追单），也是"锁定后仓位A暂时无动作"的常见原因；
- 锁定**不影响平仓窗口**：双周期模式下短周期真实信号连续两根反向时，
  锁定方向的持仓仍会走平仓窗口挂限价平仓单（锁定语义是"绝不反向开仓"，
  不是"绝不平仓"）；
- **锁定不触发反转清理的持续循环**：`long_prev` 也被锁定为同值，
  之后每轮 `long == prev_long`，`long_dir_changed` 恒 False；
- **切换锁定的一瞬间**会触发一次反转清理（旧信号方向 ≠ 锁定方向）：
  区间仓旧方向强平、新方向重挂（这正是"锁定做多后区间仓应挂多单"的路径）；
  趋势仓白天只提醒、睡眠时段强平。

### 5.4 长周期方向稳定化（未锁定时）

`long = long_prev_direction or long_raw`（L1873）：采用上一时段方向，
避免长周期震荡期频繁反转导致反复清理。

> 本地 `config_trend_range.json` 仅为 DB 故障回退。**改 JSON 不写库不生效**。

### 6.2 杠杆设置与回核（_set_leverage_if_needed，POM L723-761）

- 开仓前按仓位配置杠杆调 `set_leverage`（按 cross/isolated 分键缓存）；
- 缓存命中也**每 24 小时回交易所核对一次**实际杠杆（`LEV_VERIFY_INTERVAL=86400`，
  进程重启后首次开仓即核对）——人工在 App 改杠杆/交易所重置会使缓存失真；
- 不一致 → 告警"【杠杆校正】"并重设；重设失败清除缓存下轮重试；
  核对查询失败 → 保守信任缓存（不因校验失败阻断交易）；
- 币种级 `leverage`（如 10）同时是金额模式折算的放大因子；
  配置杠杆超过合约 `max_lever` 时自动 clamp 到上限并告警。

### 6.3 张数/金额双模式（_resolve_size，TRT L1500-1562）

- `size_mode='contracts'`（默认）：直接取 `contracts`，按合约 lotSz 向下量化；
  低于 minSz → 返回 0 并**明确告警**（不静默）；
- `size_mode='usd'`：`notional_usd` 为**占用保证金预算**：

```
张数 = floor( 金额 × 杠杆 ÷ (每张面值 ctVal × 现价) ÷ lotSz ) × lotSz
```

  向下取整（实际占用保证金不超预算）；低于 minSz 或规格/价格缺失 → 返回 0 + 告警；
  杠杆优先仓位级 → 币种级 → 1x；
- 两个仓位各自独立解析（趋势仓/区间仓可用不同模式）。

### 6.4 合约步长量化规则（2026-09-01 修复后的统一出口）

- 唯一出口：`InstrumentSpecCache.steps(inst_id)` 返回 `(lotSz, minSz)`；
  `quantize(inst_id, amount)` 向下取整到 lotSz 整数倍，低于 minSz 返回 0；
- 实测三档：XRP-USDT-SWAP = 0.01/0.01，NEAR-USDT-SWAP = 0.1/0.1，
  POL-USDT-SWAP = 1/1（差异极大，任何硬编码步长都会在某类合约上出错）；
- 规格缺失（首次拉取失败/断网）→ 回退 0.1 张（`FALLBACK_LOT_SZ`，存量行为）；
- 全链路一致：开仓量、平仓量、改量比较、粉尘阈值判定、风控上限折算、
  智能减仓保留量，一律走该出口；
- "视为无持仓"的账本粉尘阈值固定 0.01 张（`POS_DUST`，与合约无关）：
  把可交易真实小仓误判为空仓会触发重复开仓（危险），远甚于把粉尘当持仓。

### 6.5 风控上限（_place_entry 内，POM L789-824）

- 单币种上限 = 本次挂单 + 两篮子双向账本 + 已挂未成交开仓单 + 账本外真实超额；
- 总仓位上限 = 跨全部币种同口径合计；
- 超限直接拒单并告警（风控配置在交易链路强制执行，而非仅前端展示）；
- USD 口径上限按纯面值（1x 杠杆）折算，不随杠杆缩放。

## 7. 逻辑审查结论（2026-09-01）

### 7.1 四项核对结果（全部通过）
